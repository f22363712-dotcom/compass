# 💡 测评体系“双轨解耦结论”通俗解析与对比示例

> **本文档定位**：直观通俗地解释 Project Compass 测评体系中为何需要将报告结论解耦为 **Red-Line Gate（红线闸门）** 与 **Quality Grade（质量评分）** 两份独立结论，并通过汽车质检与体检的具体类比帮助理解。

---

## 一、 用生活中的“汽车质检”打个比方

想象一下，一家车厂对新出厂的汽车进行出厂质检，检查项通常自然地分为两类：

| 检查类别 | 具体检查项目 | 性质 | 评判方式 |
|---|---|---|---|
| **第一类：安全红线** | 刹车是否失灵？安全气囊是否正常？油箱是否漏油？底盘是否断轴？ | **生死线 / 底线** | **只有 PASS / FAIL**<br>（错一项就一票否决，绝不可妥协） |
| **第二类：性能质量** | 百公里加速几秒？百公里油耗是 5L 还是 8L？车机屏幕滑动的帧率？座椅舒适度？ | **性能线 / 体验度** | **连续分数与评级（如 82分、等级 B）**<br>（可以迭代优化，随着技术升级越来越好） |

### 为什么要解耦成两份独立的结论？

#### 场景 1：如果“混在一起且过度宽松”（当前 Compass 测评的现状）
- **现象**：测试员看到百公里加速只有 15 秒（性能很差），但因为安全检查合格，就在终审单上大笔一挥写着：`综合结果：PASS（优秀合格）`。
- **恶果**：**自欺欺人**。买车的人看到“PASS”，误以为这是一辆性能极佳的跑车，掩盖了发动机其实还很孱弱的真实问题。

#### 场景 2：如果“混在一起且一刀切硬挂”（方案 A）
- **现象**：测试员规定“百公里加速必须进 5 秒，否则整车不合格”。
- **恶果**：经济型小轿车直接全挂，CI 构建天天报错红屏。研发团队分不清今天报警是因为**“刹车失灵了（重大安全事故）”**，还是仅仅因为**“这辆车是 1.5L 排量本来就跑不进 5 秒（已知预期内的性能阶段）”**。

#### 场景 3：解耦后的“双轨独立结论”（方案 B）
报告明确输出两栏：
1. **【安全与底线合规 (Safety Gate)】：PASS**（刹车 100% 灵敏，零漏油，安全气囊就绪）；
2. **【动力与性能评分 (Performance Score)】：62分 / Tier 3**（百公里加速 10.2s，油耗 7.1L，建议下一阶段升级涡轮增压）。

## 二、 Project Compass 中的具体对应

在 Project Compass 评测 Coding Agent 时，一模一样：

### 轨 1：Red-Line Gate（事实不可篡改与安全红线）
这是产品的立足之本，**一票否决**：
- 任何 Agent 的提议初始必须为 `proposed`；
- 未经人类负责人明确在看板点击采纳，**哪怕测试 100% 绿灯，也绝不允许自动变成团队真理（Accepted Truth）**；
- 面对恶意对抗攻击与注入代码，准入门必须 100% 拒绝，绝不崩溃；
- 任何情况下不能读取/泄漏真实人名隐私。
- **输出**：`Red-Line Gate: [ PASS ]` 或 `[ FAIL - 发现未授权事实晋升！]`。

### 轨 2：Quality Grade（智能体抽取与检索表现）
这是模型的理解力与算法水平，**诚实量化，用于指导迭代版本**：
- **事实抽取 F1 分数**：当前是 `0.068`（216 条候选只命中 8 条，很低，诚实标出评级为 `Tier 3`，下一版目标提升到 `0.30`）；
- **原文检索命中率 (Hit@5)**：当前是 `21.4%`（14 题中命中 3 题，标出评级为 `Tier 2`，下一版目标提升到 `60%`）；
- **交接问答准确率**：当前是 `50.0%`（14 题答对 7 题）。
- **输出**：`Quality Rating: Baseline (Score: 26.1/100, Tier: C)`。

---

## 三、 解耦带来的最大价值

1. **守住红线，不让 CI 误报**：只要 Agent 没有越权篡改事实，架构底线就稳若磐石；
2. **坚守诚实，不让基线粉饰**：低分就如实呈现为低分，不会因为“为了绿灯”而把质量指标阈值设成 0.0 假装全绿；
3. **为后续迭代提供明确导航**：每次更换不同大模型（Claude、MiniMax、DeepSeek）或优化抽取算法时，我们可以直观看到 Quality Score 是从 26 分升到了 65 分，而无需担心破坏安全红线。
