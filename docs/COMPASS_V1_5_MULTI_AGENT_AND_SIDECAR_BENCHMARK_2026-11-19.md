# Project Compass v1.5.0 原生副栏、跨智能体宿主适配与实测报告

> 日期：2026-11-19  
> 版本：`1.5.0`  
> 结论摘要：在 Antigravity 内部以内置副栏插件架构托管完整主看板，比强制外开系统浏览器少占用桌面视野、无需手动记端口、可自动跟随左侧项目切换并直连输入框回传；而在 Codex、Cursor、Hermes Agent 等非 Antigravity 宿主中，单实例按需后台 Web 守护进程仅占 **`30.8 MB` 内存**（无额外 Node 进程），首次冷启动 **`1.55 s`**、热复用 **`16.2 ms`**，真正做到「各自用最轻最稳的形态交付同一个实时项目掌控台」。

## 一、调研与架构诊断：为什么右侧浏览器先前无法直接打开，两种思路各自适合什么场景？

### 1.1 根因复盘：内置浏览器的安全边界 vs 原生 Sidecar 机制
1. 先前方案默认要求用户手工运行服务后访问 `http://127.0.0.1:8787/`，若当次对话未单独拉起后台守护进程，或者内置浏览器出于本地环回隔离未开放自由地址直连，右侧面板就会显示打不开或需要额外切换桌面窗口。
2. 对照 Antigravity 原生内置的团队协同插件实现可确认：在 Antigravity 内，右侧辅助栏是通过**独立 Sidecar 插件清单**（`SIDECAR_UI_ENTRYPOINT_AUX_PANE`）与 `sidecar_sdk` 桥接进程实现的，聊天消息只需输出轻量可点击胶囊链接，由客户端内部反向代理并注入工作区桥接脚本（支持获取左侧激活工作区 URI、接收切换通知、挂入输入框评论胶囊、发送当前对话或新开专办会话）。
3. 进一步横评不同 Coding Agent 宿主可发现明显能力差异：
   - **Antigravity**：原生支持辅助栏 Sidecar 与对话内胶囊跳转，适合将完整主看板零切屏嵌在右侧，并在空闲与开关面板时按需托管生命周期。
   - **Codex / Cursor / Windsurf 等带预览栏 IDE**：多数不提供 `sidecar_sdk` 私有辅助栏扩展接口，但可展示本地预览链接或内置浏览器标签页。
   - **Hermes Agent 等纯终端 / 本地桌面 CLI**：无内置网页视口，最轻便的方式是在本地桌面首次唤醒时单次弹出系统默认浏览器并列停靠。
   - **远程 SSH / 无图形界面服务器 / CI**：无浏览器显示环境，强行 `webbrowser.open` 只会报无显示环境或打开远程无头浏览器，必须优雅降级为端口转发命令与结构化文本摘要。
   - **仅开放 MCP App 沙盒界面的桌面客户端（如 Claude Desktop / Claude.ai）**：不能随意访问任意宿主网页端口，应返回内嵌工作台资源契约作为安全兜底。

### 1.2 五档自适应交付与轻量化对比

因此 `v1.5.0` 将原本二选一的纠结收敛为**同一个后端、一套握手自动判别逻辑（`ui_delivery.tier` 五档路由）**：

| 交付档位 (`tier`) | 典型适用宿主 | 呈现形式 | 进程形态与额外开销 | 交互能力与优雅降级策略 |
| :--- | :--- | :--- | :--- | :--- |
| `antigravity_sidecar` | Antigravity（已安装 Compass 插件） | 对话内一键胶囊展开原生右侧辅助栏 | `node` 轻量代理 + 按需子进程 Web 后端 | 自动同步左侧工作区切换；`⚡ 定案并推进` 支持挂入输入框胶囊 / 直发当前对话 / 新开专办会话三档按能力显隐 |
| `ide_builtin_browser` | Codex、Cursor、Windsurf 等（本地桌面） | 单实例本地 Web 链接 `http://127.0.0.1:<port>/` | **纯 Python 单个守护进程**，空闲自动退出 | 首次按需拉起或复用已有项目端口（必要时热切换激活项目）；不强弹系统外部浏览器 |
| `external_browser` | Hermes Agent 等本机终端智能体 | 单实例本地 Web + 首次自动弹开系统浏览器一次 | **纯 Python 单个守护进程**，去重防重复弹窗 | 同一会话/URL 只自动打开一次，避免每次追问反复弹新标签页 |
| `headless_terminal` | SSH 远程开发、Linux 无 `$DISPLAY`、CI 环境 | 返回本地端口地址 + `ssh -L` 转发指引 | **纯 Python 单个守护进程**，零图形窗口调用 | 附带结构化文字摘要（核心目标 / 下一步共识 / 待拍板 / 队列） |
| `mcp_app_inline` | 声明 `io.modelcontextprotocol/ui` 扩展的宿主 | 内嵌 HTML 面板 (`ui://compass/workbench.html`) | **零独立 Web 守护进程（0 额外进程）** | 使用 MCP App 工具桥接完成定案、记草案、复核与推进，受严格负责人权限约束 |

> 补充机制亮点：日常开发与普通问答回合调用 `project_context`、`record_note`、`verify_completion` 时保持 **100% 后台静默记录**，绝不主动弹窗打断；仅当用户显式触发 `/compass`、请求打开控制台或遇到高风险阻塞需要人工可视化裁决时，才按上述五档逻辑交付界面。

### 2.2 Antigravity 真实插件注册与在线工具联调实证
1. **本机打包插件清单校验 (`GetAllPlugins` RPC)**：执行零配置安装命令后，Antigravity 语言服务实时返回已加载全局插件 `"compass"`（`"disabled": false`），包含技能 `"compass"` 与副栏声明 `"compass/compass_board"`（入口类型 `SIDECAR_UI_ENTRYPOINT_AUX_PANE`，支持网页视口与常驻重启策略），字段形态与内置原生看板保持一致。
2. **真实 Sidecar 进程联调**：通过真实 `sidecar_sdk` 加载器拉起已安装脚本，实测：
   - `GET /` 正确注入 `/preload.js` 桥接脚本；
   - 未携带副栏校验令牌请求 `POST /api/projects/activate` 被安全拦截返回 **`401`**；
   - 携带合法 `X-Sidecar-Token` 请求切换工作区成功返回 **`200`**（当次加载 `78` 条项目事实）；
   - 终止副栏宿主进程后，Python 后端通过标准输入断开监视器自动关闭，**`1.61 s` 内无残留孤儿进程**。
3. **在线 `open_compass` 工具调用**：直接通过 Antigravity 已接入的 `compass` MCP 服务调用该工具，实时返回的 `ui_delivery.tier` 精确识别当前连接客户端为 `"antigravity_sidecar"`，并生成 `[打开 Compass 实时掌控台](sidecar://compass/compass_board/)` 与最新项目焦点摘要。

## 三、跨宿主一键接入与安全边界加固要点

1. **多客户端零配置无损合并**：
   - `compass-setup --client antigravity --project-path <path> --zero-config --write`：无损合并全局 MCP 配置，并自动安装含副栏与技能文件的 Antigravity 插件包，随后也可配合 `--init-rules` 为当前仓库写入协作守则。
   - `compass-setup --client codex --project-path <path> --zero-config --write`：精准替换 `~/.codex/config.toml` 中同一服务及任意层级的环境变量/子表节，不影响已有模型与其它 MCP 服务配置。
   - `compass-setup --client hermes --project-path <path> --zero-config --write`：采用按 YAML 顶层块作用域与缩进感知的方式更新 `~/.hermes/config.yaml` 下的 `mcp_servers:`（兼容空对象 `{}`、行尾注释、4 空格缩进及同名前缀的其他配置块）。
   - `claude` / `cursor` 模式写入同样改为保留既有 `mcpServers` 条目的安全合并，并兼容空白 JSON 初始化。
2. **交互体验与竞态修复**：
   - 修复左侧连续快速切换工作区（`A -> B -> A` 往返未落盘前回切）时状态被滞后请求误覆盖的竞态问题；
   - 卡片推进按钮按当前宿主实际开放的发送与开新窗接口能力逐一显隐，避免点击无效；
   - 个人模式首次定案需要行内填写署名时，提交前提前保留备注输入框文本，防止抽屉切屏导致备注丢失；
   - 非阻塞超时控制与 `daemon_threads` 防单连接挂死，以及后端守护进程切走项目后再退出时同步清理由此持有的旧/新运行标记。
3. **安全防线（经对抗测试验证）**：
   - 全部核心写入 POST 接口强制核验回环 `Host`、`Origin` / `Sec-Fetch-Site`（拒绝 `Origin: null`、跨站与非法 URL）以及内容类型限制，阻断浏览器 CSRF 表单与简单请求攻击；内部副栏代理仅当本机回环连接、ASCII 可比对且匹配随机密钥时放行；
   - 工作区路径解析明确拒绝含非本机网络域名的远程 `file://` UNC 路径，防止触发隐式 SMB 外联；
   - 统一 `SAMPLE_MODE=true` 在副栏与守护进程模式下的纯只读示例语义，绝不污染真实项目目录；
   - 公开发布导出扫描验证持续保持 **0 条本机隐私或密钥泄露**，L4–L5 基准评测保持完整通过。

## 四、实景阻塞与深色宿主撞色问题深度根治及前后量化对比

### 4.1 现场病根诊断
1. **卡在「正在同步工作区…」与 65 线程锁排队积压**：
   - 首次反序列化 1,649 个代码结构节点时对重复文件路径逐条解析绝对路径，耗时高达 **`4085.9 ms`**；
   - 每次状态刷新均全量重算 78 条事实投影并遍历核对目录指纹（单次耗时 **`882.7 ms` ~ `1889.0 ms`**）；
   - 副栏初始化挂载时又对已加载同一目录（Windows `file:///` URI 编码差异）再次触发切区接口，叠加前端 8 秒超时后自动重试与定时轮询，导致后端累积 **65 个阻塞线程**、接口在 15 秒内超时卡死。
2. **深色宿主下黑底黑字与右上角状态框白底白字**：
   - Antigravity 副栏运行时在深色模式下会向根节点注入行内纯黑背景与浅色 `--muted` 变量，覆盖了原本面向浅色纸面设计的主看板颜色，导致大标题变成黑底黑字、右上角连接徽标变成白底白字。

### 4.2 根治改造与同机前后实测对比
- **样式强隔离**：将看板自身调色盘独立固化为 `--c-*` 源变量并在容器根节点以最高优先级锁定米白纸面 `#F4F3EE`（`rgb(244, 243, 238)`）与深墨字色 `#090D16`（`rgb(9, 13, 22)`），同步锁定表单控件配色方案为浅色。
- **百倍路径去重、快照复用与非阻塞退让**：结构加载按去重后的相对路径集合一次性校验权限；相同修订号下状态接口直接复用深拷贝快照并用轻量级元数据签名缓存目录新鲜度；接口持锁繁忙时允许读请求快速退让返回最新稳定快照；副栏端规范化比对 `file://` 路径与本地路径以跳过重复切区，并保持 8 秒有界首屏超时契约与扩大监听队列容量至 64。
