## 一、语言、框架与存储选型结论

结合 [PRODUCT_FORM_AND_TECH_STACK.md](PRODUCT_FORM_AND_TECH_STACK.md)、[DECISIONS.md](../DECISIONS.md) 及仓库根目录 `AGENTS.md` 的硬约束，Compass v1.6 明确**不推翻重写、不引入外部数据库或重型智能体框架**，保持如下技术栈：

| 层级 | 技术选型 | 选型原因与红线约束 |
| :--- | :--- | :--- |
| **后端与推理引擎** | **Python 3.10+ 纯标准库（`dependencies = []`）** + 标准库 `ast`、`json`、`hashlib`、`threading`、`urllib.request` | `pyproject.toml` 与开源门禁要求零第三方运行时依赖；项目账本为百级至千级记录，内存折叠计算实测 `< 25 ms`，无需引入外部图数据库或向量库。 |
| **前端工作台** | **零构建 Vanilla ES2022 JS + CSS3 + HTML5 Canvas** | 匹配原生伴侣工作台与 Antigravity Sidecar 副栏直连托管模式，零构建链、首屏加载 `< 2s`。 |
| **模型接入策略** | **「本地高精度确定性规则 + 可插拔大模型异步增强」双轨混合** | `SAMPLE_MODE=true` 或无密钥环境下 100% 离线可用；配置 Claude / DeepSeek / MiniMax / Ollama 后，后台按游标增量增强隐含前提提炼、方案权衡与盲评。 |
| **持久化账本** | **保持现有追加式 JSON 状态格式向后兼容** | 通过扩展事件 `metadata` 挂载因果关联与生命周期状态，不破坏现有单测与既有 `.project-memory` 存档回放。 |

## 三、Compass 的差异化破局路线

市面上现有方案往往落入两极：**黑盒后台记忆**（用户看不见全貌、分不清已拍板与随口脑洞，如无界面记忆服务）或 **静态归档日志**（不感知实时对话分叉与底层代码变更，如纯手写 ADR）。

Compass 独一无二的产品位在于构建 **「左写右长实时因果沙盘 + `proposed` / `accepted` 防抢跑门禁 + 代码爆炸半径联动 + 倒金字塔溯源核查」** 的人机协同控制台。v1.6 沿以下三步演进：

### 演进一：被动双通道无感采集与历史降噪（先治“采集盲区”与“噪音/假冲突”）
1. **接通原生会话日志增量旁听**：把仓库已有的按字节游标增量读取器接入右栏 Sidecar 与本地后台服务，按项目目录与文件修改时间自动发现活跃的 Antigravity / Codex 本地会话日志，仅读取完整行并剥离隐藏推理链（`thinking`）与敏感凭据，在 1.5–3 秒节流窗口内自动增量抽取新目标、方案决策、并列选项与前提，全部锁死为 `proposed` 候选，绝不自动覆盖正式基准。
2. **历史归档降噪与完工过滤**：文档扫描器跳过 `docs/archive/`、`docs/superpowers/` 与带历史日期戳的评测/审查快照文档（`*_2026-*.md`），同时严格将已勾选 `[x]` 或已达成里程碑从“活跃待办”中剔除；当实时会话已有未决草案时，不再把陈旧静态文档条目挤入紧凑上下文首屏待拍板队列。
3. **消解单人/跨期误报假冲突**：保留底层不可变事件引擎不变，在投影展示层精准区分“多成员并列分歧”与“同一成员按时间演进更新锚点（或实时新提案演进旧文档）”，彻底消除单人演进被标红为“存在分歧”的误报。

### 演进二：因果—前提—淘汰路径轻量图谱（让内容“立体可推演”）
1. **结构化会话语义抽取（本地正则状态机 + 可插拔增量 LLM 观察器）**：在不新增第三方依赖的前提下，从对话原文精确切片抽取四类信息：
   - **已定决策（`settled`）**：明确拍板采纳的结论；
   - **待决分叉（`open_fork` + `alternatives`）**：并列权衡中的选项 A / 选项 B；
   - **依赖前提（`assumption` + `premise_status`）**：关联决策成立所需的前提条件（随后续 `test_result` 通过/失败自动联动核验态：`unverified` / `verified` / `invalidated`）；
   - **已淘汰路径（`rejected_path` + `rejection_reason`）**：明确否决的做法及其淘汰原因。
2. **严守 L4 调用链契约边界**：新增独立的图谱组装与增强模块，只消费投影后的结构化事实与证据列表，绝不反向侵入受契约保护的底层核心函数调用链。
3. **模型增强严格原话锚定校验**：开启可选云端/本地大模型异步语义观察器时，每一条模型提炼的隐含前提或并列选项，必须在对应源消息全文中找到连续精确原文子串，否则直接丢弃，杜绝幻觉编造。

### 演进三：克制型高信噪比策略顾问（从“书记员”升级为“首席架构顾问”）
彻底超越旧版仅检测“空目标、最近失败、最近 3 次编辑无字面重合”的表层规则，建立五维触发 + 宁缺毋滥沉默门禁：
1. **流沙前提预警（`未验前提`）**：关键待定方案或当前下一步依赖的前提尚未实测验证，或已被最新命令执行证伪时立即亮灯。
2. **废案复发与契约波及预警（`盲区预警`）**：近期修改或新提议撞上历史已淘汰路线，或修改文件命中 AST 高扇入核心模块时，给出原因溯源与影响范围。
3. **分叉收敛提醒（`方案权衡`）**：存在多个并列备选方案或多人真实分歧长期悬而未决时，凝练并列分叉供负责人拍板。
4. **过时锚点纠偏（`偏航提醒`）**：当前对话重心或已完成状态已跨越顶栏锁定锚点时，提醒同步更新下一步。
5. **诚实沉默门禁（`Abstention`）**：以上信号均未命中高置信度证据时保持安静（或前端展示一键忽略后会话级退避），并强制要求每条 LLM 顾问输出附带真实存在且非空的有效证据编号或明确降级，绝不输出无依据的空泛客套。

## 四、三项量化评测与验证计划
保留当前 `v1.5` 行为作为对照基线，构建三套端到端评测标尺输出可复现的真实数据：
1. **采集链路对照实验（Track 1）**：对比关闭自动监听 + 全量旧文档扫描 vs 开启 `AutoTranscriptIntake` + 归档降噪 + 同人演进消解，量化新决策捕获率、下一步时效性、静态噪音压降与假冲突清零。
2. **真实里程碑标准答案盲测（Track 2）**：构建涵盖 18 个脱敏真实研发节点的黄金语料，同题对比 `v1.5 基线`、`v1.6 纯本地规则`、`v1.6 大模型增强` 在已决决策、未决备选、依赖前提与淘汰路径上的 Precision / Recall / F1。
3. **隔离上下文策略顾问盲评（Track 3）**：构造 8 类关键研发现场（流沙前提、废案重提、二选一悬而未决、锚点滞后、AST 波及、命令失败、正常静默等），交由零上下文评审模型从有用性、事实准确度、时机恰当度、低打扰度四维盲评打分。
